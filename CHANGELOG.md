# Changelog

Все значимые изменения проекта NEXUS WORKSPACE. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [SemVer](https://semver.org/lang/ru/).

Первая публичная версия — 1.0.0. История ниже описывает состав релиза, а не

## [Unreleased]

### Added

- **NEXUS AI Workspace.** AI Chat и Agent Mode: потоковые ответы PolyStrata,
  сохранение диалогов/сообщений, вложения, повтор/редактирование/остановка,
  оркестрация Agent Task, approvals, Skills, изолированные workspace и квоты.
  Backend-модуль `ai` (миграция `0019`, права `ai.*`, module gate), frontend
  `/workspace/ai` и `/system/ai`, OpenAPI 3.1 и документация
  `docs/AI_WORKSPACE.md`.
- **NEXUS AI Runtime.** Отдельный Windows executable/служба на компьютере с
  PolyStrata: исходящий WSS без входящих портов, одноразовый enrollment,
  отзывной device token, heartbeat/reconnect, OpenAI-compatible клиент с SSE,
  безопасные файловые инструменты, зарегистрированные программы, лимиты,
  идемпотентность и отмена. Install/update/uninstall PowerShell scripts и
  `runtime check`.

- **Проверка каталога перед регистрацией тома.** Сервер сканирует
  `.nexus/objects`, `staging` и `quarantine` выбранного каталога и показывает
  найденные файлы в диалоге. Непустой объектный каталог нельзя зарегистрировать
  молча: требуется явный импорт (`adoptOrphans`) или ручная очистка. Импорт
  считает SHA-256, создаёт записи `storage_objects` и служебную ссылку
  `system`, поэтому файлы не остаются «осиротевшими» и не удаляются
  автоматической очисткой. Удаление регистрации дополнительно блокируется при
  файлах в `.nexus/objects`, которых нет в БД. Новый endpoint
  `POST /api/v1/storage/volumes/scan`.
- **Снятие сборки Minecraft с публикации.** Кнопка в списке сборок и на
  странице сборки: опубликованные и устаревшие релизы обоих каналов получают
  статус `unpublished` и исчезают из каталога, версий, манифестов и файлов
  лаунчера; сборка возвращается в черновики. Снимки сохраняются, поэтому релиз
  можно опубликовать снова. Миграция `0017`, endpoint
  `POST /api/v1/minecraft/builds/{id}/unpublish`, событие WebSocket
  `build.unpublished`.
- **Совместимость с MyLauncher (собственный репозиторий).** Публичные
  endpoints ровно по коду клиента: `GET /api/packs`,
  `/api/packs/{packId}/versions`, `/api/packs/{packId}/versions/{version}/manifest`,
  `/api/packs/{packId}/icon`, `/api/files/sha256:{hex}`. Ответы без обёртки
  `{success,data}`, как ожидает Rust-парсер лаунчера.
- Манифест `manifestVersion: 1` с `sha256:`/`/api/files/...`, фильтрацией
  `side=client|both`, проверкой расширений/ASCII-путей/лимитов 8 ГиБ и 20 ГБ,
  точной Java по версии MC и загрузчиками vanilla/fabric/forge/neoforge.
- Каналы релизов `stable`/`beta` (миграция `0015`), независимый latest и
  список версий по каналу.
- Неизменяемый снимок лаунчер-манифеста при публикации:
  `launcher_manifest`, `launcher_manifest_hash`, `launcher_manifest_schema`.
- Launcher-ready проверки блокируют публикацию несовместимых сборок;
  `REQUIRED_DISABLED`, `LAUNCHER_PATH`, `LAUNCHER_JAVA` и др.
- Публичная страница интеграции «Подключение MyLauncher»: адрес из
  `NEXUS_PUBLIC_URL`, инструкция, проверка каталога, endpoints, ограничение
  токенов.
- Страница релиза: канал, точный JSON MyLauncher, копирование URL манифеста.
- Документы `docs/LAUNCHER_CONTRACT.md`, `docs/schemas/launcher-manifest-1.json`,
  `docs/admin/launcher.md`.

- **Файловый менеджер сборки (каноническое дерево инстанса).** Двухпанельный
  интерфейс: дерево `options.txt / mods / shaderpacks / resourcepacks / config`
  со счётчиками и размерами, таблица выбранной папки, хлебные крошки и полные
  пути с копированием, поиск/фильтры/сортировка, массовый выбор и операции.
- Загрузка Drag & Drop файлов и папок из проводника с рекурсивным обходом
  `webkitGetAsEntry`, сохранением структуры `config`, подсветкой целей и
  предпросмотром неоднозначных drop (`.zip` → resourcepacks/shaderpacks) с
  редактируемым путём и стратегиями переименовать/заменить/пропустить.
- Внутренний DnD перемещения файлов и папок, создание/переименование (F2)/
  перемещение/удаление, замена `options.txt`, текстовый просмотр, правый drawer
  настроек с живой валидацией пути.
- Очередь загрузки артефактов: параллельность 2, пауза/продолжение с серверного
  offset, повтор, отмена, прогресс/скорость/ETA, события WebSocket.
- Серверная проверка канонических путей на каждой мутации: ASCII-политика,
  allowlist расширений, `options.txt` в корне, плоские `mods`/`shaderpacks`/
  `resourcepacks`, вложенный `config`, запрет `versions/assets/libraries`,
  резервных имён Windows и коллизий регистра/Unicode. Legacy-категории
  (`scripts`, `overrides`, `other`) сохранены.
- Миграция `0016`: режим замены хранится в сессии загрузки и переживает паузу,
  resume и повторную фиксацию.
- Аудит `minecraft.folder.created`, `minecraft.artifact.updated`,
  `minecraft.artifact.deleted`.
- Contract-тесты `launcher_repository_tests.rs` (7) и unit-тесты формата.

### Fixed

- **Сборка оставалась черновиком после публикации релиза.** Публикация
  идемпотентно восстанавливает статус `published` и текущий релиз, если сборку
  ранее вернули в черновики; активация опубликованного релиза («Сделать
  текущим») больше не оставляет сборку в статусе `draft`. Архивирование или
  пометка «Устарел» для текущего релиза переключает сборку на другой
  опубликованный релиз, а при его отсутствии возвращает в черновики — вместо
  рассинхронизации «опубликована в интерфейсе, отсутствует в лаунчере».
  Каталог `/api/packs` отдаёт только сборки со статусом `published`.
- **Кнопка «Опубликовать» теперь требует проверки.** Перед публикацией UI
  выполняет `validate`, показывает отчёт, блокирует действие при ошибках и
  запрашивает подтверждение при предупреждениях; `acceptWarnings` больше не
  передаётся скрыто. После создания релиза открывается вкладка «Релизы», чтобы
  черновик можно было сразу опубликовать.
- **Ручной ввод версии загрузчика в сборках.** Мастер и редактор сборки
  подбирают версию загрузчика автоматически из списка, совместимого с выбранной
  версией Minecraft; ручной ввод убран, а несовместимая пара отклоняется API.
  Справочник `/metadata/loaders` теперь запрашивает официальные API загрузчиков
  при промахе кеша, корректно сопоставляет NeoForge 1.20.1 (`47.1.x`) и годовые
  версии, а также не теряет свежие версии Forge/NeoForge из Maven.
- **Сопоставление версий загрузчиков в MyLauncher и серверах.** Для NeoForge
  исправлены линейка `47.1.x` для 1.20.1, доступность версии `1.21` без патча и
  точное сопоставление годовых версий; установка сервера проверяет, что выбранная
  версия загрузчика входит в список совместимых.
- **Каталог MyLauncher игнорировал текущий релиз после отката.** `/api/packs`
  и `/api/packs/{packId}/versions` выбирали релиз по времени публикации, поэтому
  после «Сделать текущим» лаунчер продолжал предлагать более новый релиз. Теперь
  первым выбирается `current_release_id` в пределах запрошенного канала; покрыто
  контрактным тестом.
- **Опубликованная приватная сборка не видна в лаунчере без объяснения.** На
  странице сборки показывается видимость, предупреждение «не видна в MyLauncher»
  и действие «Сделать публичной»; список сборок помечает private как
  «не в лаунчере»; мастер создания и страница Launcher API предупреждают, что в
  каталог попадают только публичные сборки.

- **Потеря фокуса во всплывающих формах.** Общий `Modal` перезапускал effect
  на каждом keystroke из-за нестабильного `onClose` в зависимостях и переводил
  фокус на крестик. Теперь callback хранится в ref, эффект зависит только от
  `open`, начальный фокус ставится в первое редактируемое поле (или заголовок),
  Tab замыкается на границах, Esc работает, фокус возвращается на триггер.
  Регрессии покрыты Vitest и Playwright.
- `416` с `Content-Range` для недостижимого `Range` у артефактов лаунчера;
  Cloud сохраняет прежнее поведение (полный `200`).
- Тесты сессий и публичных ссылок приведены в соответствие с кэшем сессий и
  проверкой пароля на устаревшем пути скачивания.
- 3D-фон: смена палитры теперь применяется к уже созданному WebGL-движку.
  Раньше палитра кешировалась при создании сцены, поэтому предпросмотр не
  реагировал до переключения вкладки, а системный default не менял цвета фона
  на форме входа, если движок успевал создаться до загрузки настройки.
- 3D-фон: публичный `GET /api/v1/public/appearance/background` отдаётся с
  `Cache-Control: no-store`, чтобы новый системный default сразу применялся на
  страницах без сессии.
- 3D-фон: системное значение из `appearance.background.defaults` теперь
  применяется и на страницах без сессии (форма входа, публичные ссылки), а не
  только к авторизованным пользователям без личных настроек. Добавлен
  публичный `GET /api/v1/public/appearance/background`, возвращающий только
  эффективные параметры фона. Изменять системное значение по-прежнему может
  только пользователь с правом `system.settings.manage`.

## [1.0.0] — 2026-11-20

Целевая и единственная платформа релиза — **Windows 11** (служба
`NexusWorkspace`).

### Added

**Платформа**

- Модульный монолит на Rust 2024 / Axum 0.8 / Tokio / SQLx 0.8 / PostgreSQL:
  модули `auth`, `users`, `permissions`, `storage`, `cloud`, `minecraft`,
  `launcher`, `realtime`, `system`, `api`, `core`.
- CLI `nexus serve | migrate | create-admin | check [--json]`; проверка
  конфигурации, БД, миграций, статики, томов, администратора и каталога логов.
- Единый контракт `{success,data}` / `{success:false,error,request_id}`,
  коды ошибок (`FILE_NAME_CONFLICT`, `MODULE_DISABLED`, `QUOTA_EXCEEDED`,
  `RATE_LIMITED`, `DOWNLOAD_LIMIT_REACHED`, `INSUFFICIENT_SPACE` и др.).
- OpenAPI 3.1: **107 путей / 132 операции**, `docs/openapi.json` и
  сгенерированная таблица `docs/API.md`; Swagger UI только при
  `NEXUS_ENABLE_DOCS=true`.
- 14 миграций PostgreSQL (`0001`–`0014`), включая паузу фоновых задач,
  auth-only ссылки, владельца сборок и область томов.
- Документация A1–A12 в `docs/`: ARCHITECTURE, DATABASE, API, MANIFEST +
  JSON Schema, SECURITY, ADMIN_GUIDE, USER_GUIDE, DEPLOYMENT, TESTING,
  карта `docs/README.md`; инструкция `docs/INSTALL-WINDOWS.md`.

**Cloud Storage**

- Файловый менеджер: папки, список/сетка, поиск, сортировка, избранное,
  «Все файлы», «Недавние» (фильтр по дате), «Общий доступ», корзина,
  массовые операции, фильтр по типу.
- Возобновляемые потоковые загрузки чанками с серверным offset, паузой,
  продолжением, отменой, TTL и очисткой просроченных сессий; очередь в
  браузере с параллельностью, скоростью, ETA, повтором и восстановлением
  после перезагрузки.
- Загрузка папок с сохранением структуры; лимиты **2000 файлов / 100
  уровней** проверяются и на клиенте, и на сервере.
- Скачивание с `Content-Length` и HTTP Range; массовое скачивание в ZIP
  фоновой задачей с прогрессом и настраиваемым TTL.
- Предпросмотр изображений, видео, аудио, текста, кода (highlight.js) и PDF
  (PDF.js, отдельные lazy-chunks); HTML/JS/SVG не исполняются inline.
- Публичные ссылки: срок, пароль, лимит скачиваний, отзыв; режим

**Minecraft Build Manager**

- CRUD сборок, клонирование, архивирование, восстановление, иконка
  (PNG/JPEG/WEBP по сигнатуре, ≤ 2 МБ), видимость, владелец.

- Релизы: `draft`/`validating`/`ready`/`published`/`archived`/`deprecated`,

### Changed

- Версия продукта поднята до **1.0.0** в `backend/Cargo.toml` и
  `frontend/package.json`.
- Максимальный размер тела запроса для `/cloud` и `/minecraft` — 256 МБ

  (`limits.chunk_max_mb`), ошибка `413 CHUNK_TOO_LARGE` содержит

- Лимиты загрузки, TTL сессий/ссылок/экспорта, квоты, TTL сессии и порог
  блокировки входа, минимальная длина пароля и `jobs.max_concurrent`

  страховка).
- CORS и `trust_proxy` применяются из `system_settings` при старте, с
  приоритетом над `nexus.toml`/env; UI явно помечает «после перезапуска».
- Манифест релиза сортируется в Rust байтово, а не через SQL `lower(path)`,
  чтобы порядок не зависел от коллации.
- Кеш манифеста лаунчера больше не перезаписывает материализованный документ.
- `ApiError` поддерживает заголовки ответа; они сохраняются вместе с
  `request_id`.
- `prefers-reduced-motion` отключает анимацию 3D-движка (статичный кадр),
  а не только CSS-переходы.
- Внешний вид и 3D-фон разделены на `/system/appearance` и
  `/system/background`.
- Миграции применяются только forward; откат обновления возвращает бинарник,
  но не схему БД.

### Fixed

**Windows / NTFS-инварианты**

- Зарезервированные имена (`CON`, `PRN`, `AUX`, `NUL`, `COM1–9`, `LPT1–9`,
  в том числе с расширением) отклоняются `422`, а не создают файл.
- Завершающие точка и пробел больше не срезаются молча — имя отклоняется.
- ADS-двоеточия (`file.txt:payload`) и недопустимые символы
  `< > : " / \ | ? *`, управляющие символы — `422`.
- Полный путь ограничен бюджетом 240 UTF-16 единиц (запас под корень тома и
  `.nexus/exports`): `422 PATH_TOO_LONG` с `maxLength`/`actualLength`,
  без обрезания.
- Регистронезависимые коллизии имён (`Mods/A.jar` и `mods/a.jar`) дают
  `409 FILE_NAME_CONFLICT`, а не перезапись; гонка между проверкой и
  `insert/update` (`23505`) тоже превращается в `409`, а не `500`.
- `ERROR_SHARING_VIOLATION` / `ERROR_LOCK_VIOLATION` (32/33) при удалении
  объектов и ZIP обрабатываются retry с backoff `25/50/100/200/400 мс`;
  строка `storage_objects` сохраняется до фактического удаления, экспорт
  отдаёт `409 FILE_LOCKED`.
- Обход через junction/symlink за корень тома запрещён: канонизация и
  проверка reparse points дают `422`; UNC-пути отклоняются с объяснением.
- Скачивание отдаёт `filename*` по RFC 5987, поэтому не-ASCII имена
  (`Отчёт 2026 (итог).txt`) сохраняются в Chromium/Edge.
- MIME определяется по сигнатуре: `.png` с текстом → `text/plain`, HTML/SVG →
  `attachment` + `application/octet-stream`, JS → `text/plain`; поддельный
  `Content-Type` клиента игнорируется.
- `.env` ищется рядом с `nexus.exe` при старте службы из `System32`;
  переменные пользователя (`setx`) в службу не попадают — задокументировано.

**Платформа**

- `Idempotency-Key` покрывает завершение загрузок Cloud/Minecraft, замену
  файла, создание ссылок и экспортов; параллельный повтор даёт `409`,
  другой body — `422`, успешный результат воспроизводится без дублей.
- Пауза задачи сохраняет прогресс и освобождает слот; после рестарта
  «зависших» `running` нет.
- PDF открывается через PDF.js в обход прежнего ограничения CSP; CSP:
  `frame-src 'none'`, `object-src 'none'`, `worker-src 'self' blob:`,
  `script-src 'self'`.
- «Недавние» действительно фильтруются по дате; TTL ссылки и экспорта
  берутся из настроек.
- Удаление тома с данными и удаление объекта с внешними ссылками не
  выполняются (`VOLUME_NOT_EMPTY`, проверка `storage_object_refs`).
- При `prefers-reduced-motion: reduce` статичный кадр 3D-фона перерисовывается
  после `ResizeObserver`: раньше изменение размера очищало canvas и главная
  оставалась с пустой подложкой (L3, визуальная приёмка).

### Security

- Argon2id для паролей; в БД хранится только SHA-256 хеш токена сессии,
  cookie `HttpOnly` / `SameSite=Lax` / `Secure` при HTTPS.
- CSRF: HMAC-SHA256 от токена сессии, обязательный `X-CSRF-Token` для всех
  изменяющих запросов; защита от brute-force (in-memory 5/15 мин и порог
  неудач в БД), выравнивание времени ответа.
- RBAC: 20 разрешений, deny-overrides, проверка прав на сервере в каждом
  обработчике; отключение модуля блокирует API без перезапуска.
- Приватные сборки лаунчера изолированы на каталоге, манифестах, иконке и
  артефактах; ответ `404` не раскрывает существование.
- Публичные ссылки «только для авторизованных» требуют действующую сессию
  даже при наличии пароля.
- Финальные заголовки безопасности: CSP, `X-Content-Type-Options`,
  `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`.
- Потоковая передача файлов без загрузки в RAM; проверка сигнатур;
  внутренние пути, SQL и трассировки не попадают в ответы API и журнал.
- Секреты (`NEXUS_SECRET`, `DATABASE_URL`) хранятся только в `.env` на сервере
  и не входят в release-архив.
- Аудит `settings.system.updated` хранит старое и новое значение без
  секретов; `job.failed` дублируется в журнал событий.

## Известные ограничения 1.0.0

- Delta-обновления сборок и шаринг файлов между пользователями — задел на
  будущие версии, в 1.0.0 не реализованы.
- «Активные соединения» = in-flight HTTP + WebSocket; переносимого подсчёта
  TCP нет. «Скорость дисков» = IO процесса NEXUS.
