# Подключение MyLauncher

NEXUS отдаёт опубликованные сборки в формате репозитория MyLauncher. Клиент
подключается по адресу сервера и не требует изменения своего кода.

## 1. Предварительные условия

1. Модуль `minecraft` включён (система → модули).
2. Есть хотя бы одна **публичная** сборка со статусом `published` и
   опубликованным релизом канала `stable` или `beta`.
3. Релиз прошёл launcher-ready проверку: путь и расширение каждого файла
   совместимы с клиентом, Java совпадает с требованием Minecraft, загрузчик —
   `vanilla`, `fabric`, `forge` или `neoforge`.
4. `NEXUS_PUBLIC_URL` содержит внешний адрес сервера (например,
   `https://nexus.example.com`). От него строится `iconUrl` каталога.

## 2. Адрес репозитория

Откройте в панели **Launcher API** → карточку «Подключение MyLauncher».
Скопируйте адрес вида:

```
https://nexus.example.com
```

Если NEXUS развёрнут в подкаталоге, укажите его: `https://host/nexus`.
Клиент сам добавит `/api/packs`.

Допустим HTTP только для локальной сети: `localhost`, `*.local`, частные
IPv4/IPv6. Публичный HTTP-адрес клиент отклонит.

## 3. Действия в MyLauncher

1. Откройте раздел «Собственные сборки».
2. Вставьте адрес репозитория.
3. Выберите канал `stable` или `beta`.
4. Нажмите «Подключить» — появится каталог.
5. Выберите сборку и версию, укажите имя инстанса и подтвердите доверие
   источнику.

Токен вводить не нужно и некуда: stock MyLauncher не отправляет токен и
запрещает query/учётные данные в URL.

## 4. Токены и приватность

Раздел «Токены лаунчера» (`launcher.manage`) остаётся для внутреннего
Launcher API `/api/v1/launcher/*` и будущих клиентов, которые умеют
`Authorization: Bearer`.

* Публичные сборки доступны без токена — так работает stock MyLauncher.
* Приватные сборки не видны без токена. Этот клиент их не получит: передать
  токен ему нечем. Ограничение зафиксировано в
  [LAUNCHER_CONTRACT.md](../LAUNCHER_CONTRACT.md).
* При наличии заголовка сервер проверяет scopes `launcher.catalog` и
  `launcher.artifacts`; отозванный токен даёт `401`.
* Rate limit репозитория: по токену либо по IP; при превышении — `429` с
  `Retry-After`.

## 5. Проверка

Кнопка «Проверить каталог и манифест» на странице Launcher API запрашивает
`/api/packs?channel=...` и первый манифест тем же путём, что клиент, и
показывает число сборок, `manifestVersion` и число файлов.

Ручная проверка:

```powershell
$Base = "https://nexus.example.com"
Invoke-RestMethod "$Base/api/packs?channel=stable"
Invoke-RestMethod "$Base/api/packs/my-pack/versions?channel=stable"
Invoke-RestMethod "$Base/api/packs/my-pack/versions/1.0.0/manifest?channel=stable"
```

Последний ответ должен содержать `"manifestVersion": 1`, `files[].hash` с
префиксом `sha256:` и `files[].url` вида `/api/files/sha256:...`.

## 6. Типовые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Каталог пуст | Нет публичной сборки/релиза в выбранном канале | Опубликуйте релиз, проверьте visibility и channel |
| `404` на версии | Версия принадлежит другому каналу | Выберите правильный канал |
| Клиент отклоняет URL | Публичный HTTP, query или учётные данные | Используйте HTTPS без query |
| Публикация блокируется | Launcher-ready ошибка | Исправьте путь/расширение/Java/загрузчик |
| Иконка не видна | `iconUrl` не HTTPS | Настройте HTTPS через Caddy |
