# Установка и первый запуск

> Часть руководства администратора NEXUS WORKSPACE. Полный индекс — [ADMIN_GUIDE.md](../ADMIN_GUIDE.md).

## Введение

Документ описывает **фактический** интерфейс и поведение системы на
19.11.2026: первый запуск, пользователей и права, квоты, диски и тома,
отключение модулей, фоновые задачи, мониторинг, журнал, системные настройки,
резервное копирование, обновление и типовые ошибки.

Руководство рассчитано на администратора, у которого есть доступ к серверу,
службе NEXUS и PostgreSQL. Установка, HTTPS и настройка обратного прокси
подробно разбираются в [`DEPLOYMENT.md`](DEPLOYMENT.md); работа пользователя
в Cloud и Minecraft — в [`USER_GUIDE.md`](USER_GUIDE.md).

Обозначения:

* ✅ — работает в текущей сборке;
* ⏳ — значение сохраняется, но ещё не применяется обработчиками; задача
  указана (фаза B/C);
* ⚠ — осознанное ограничение или обязательное действие администратора.

Связанные документы: [`ARCHITECTURE.md`](ARCHITECTURE.md),
[`API.md`](API.md), [`SECURITY.md`](SECURITY.md),
[`MANIFEST.md`](MANIFEST.md), [`openapi.json`](openapi.json),
[`../README.md`](../README.md).

## 1. Первый запуск

### 1.1. Что должно быть готово

| Компонент | Требование |
|---|---|
| ОС | Windows 11 / Windows Server |
| PostgreSQL | 14+ (проверено на 17), отдельная роль и база NEXUS |
| Свободное место | под PostgreSQL, журналы и каталоги хранения |
| Порты | `8080` для NEXUS (по умолчанию), наружу — только через прокси |
| HTTPS | обязателен для production; иначе cookie `Secure` выключается |
| Учётная запись службы | права чтения/записи на каталоги хранения и журналы |

База создаётся заранее:

```sql
create role nexus login password '<пароль>';
create database nexus owner nexus;
```

Пароль и строка подключения попадут в `DATABASE_URL`. Пользователь
PostgreSQL не должен быть суперпользователем и не должен быть доступен из
интернета.

### 1.2. Установка

**Windows** (PowerShell от имени администратора):

```powershell
powershell -ExecutionPolicy Bypass -File deployment\install-windows.ps1 `
  -Domain nexus.example.com `
  -DatabaseUrl "postgres://nexus:<пароль>@127.0.0.1:5432/nexus"
```

Скрипт `deployment/install-windows.ps1`:

1. собирает backend и frontend (если не указан `-SkipBuild`);
2. создаёт `C:\NexusWorkspace` с каталогами `logs`, `data`, `frontend`;
3. копирует `nexus.exe`, `nexus.toml` и пример `.env`;
4. создаёт `.env` со случайным `NEXUS_SECRET`, путями и публичным URL;
5. применяет миграции и выполняет `nexus check`;
6. создаёт администратора `admin`, если администраторов ещё нет;
7. регистрирует и запускает службу `NexusWorkspace`.

⚠ Windows без `-DatabaseUrl` записывает заглушку `CHANGE_ME`. Миграции с ней
не пройдут, и установка остановится — передайте `-DatabaseUrl` при установке.

Администратор создаётся установщиком; если его ещё нет, выполните:

```powershell
.\nexus.exe create-admin --username admin
```

### 1.3. Обязательные команды

Все команды выполняются из каталога установки (`C:\NexusWorkspace`), где лежат
`nexus.exe`, `.env` и `nexus.toml`:

| Команда | Назначение |
|---|---|
| `nexus migrate` | применить миграции и синхронизировать каталог прав |
| `nexus create-admin --username admin` | создать первого администратора (пароль запрашивается интерактивно) |
| `nexus update-admin` | изменить супер администратора (если их несколько, выбрать по номеру; логин и имя опционально сохраняются, пароль вводится один раз) |
| `nexus update-admin --username <login>` | выбрать супер администратора по логину, если их несколько |
| `nexus check` | проверить конфигурацию, БД, миграции, статику, тома и администратора |
| `nexus check --json` | тот же результат в машиночитаемом виде для скриптов |
| `nexus serve` | запустить HTTP-сервер (обычно запускает служба) |

Пароль можно передать без интерактивного ввода:

```powershell
$env:NEXUS_ADMIN_PASSWORD = '<пароль>'
.\nexus.exe create-admin --username admin --password-env NEXUS_ADMIN_PASSWORD
Remove-Item Env:NEXUS_ADMIN_PASSWORD
```

Требования к паролю: 12–128 символов, есть буквы и цифры. Логин: 3–32
символа, латинские буквы, цифры, точка, дефис, подчёркивание.

`create-admin` всегда создаёт **суперадминистратора** и назначает ему
системную роль `administrator`. Если администратор потерял доступ, создайте
второго администратора с другим логином — CLI не сбрасывает пароль
существующей учётной записи.

### 1.4. Проверка готовности

```text
nexus check
  база данных: подключение успешно (PostgreSQL 17.x)
  миграции: 10
  тома хранения: 1
  администраторы: 1
  статика: C:\NexusWorkspace\frontend
  каталог логов: C:\NexusWorkspace\logs
Проверка пройдена: сервер готов к запуску.
```

Код возврата `0` — проблем нет, `1` — есть. Проверка контролирует:

* длину и «заводское» значение `NEXUS_SECRET`;
* согласованность `public_url` с `NEXUS_COOKIE_SECURE`;
* подключение к PostgreSQL, наличие миграций;
* наличие хотя бы одного администратора;
* наличие `frontend/dist/index.html`;
* доступность каталога журналов.

Отсутствие томов хранения — предупреждение, а не ошибка. Но без тома
загрузка файлов невозможна (`NO_VOLUME_AVAILABLE`), поэтому зарегистрируйте
каталог сразу после первого входа (раздел 4).

### 1.5. Первый вход

1. Откройте `NEXUS_PUBLIC_URL` (например, `https://nexus.example.com`).
2. Войдите логином и паролем администратора.
3. Если пользователей в базе нет, страница входа выведет подсказку о
   создании администратора и не пустит в систему.
4. После входа проверьте:
   * **Система → Состояние** — версия, БД, модули, диски;
   * **Система → Хранилища** — добавьте каталог хранения;
   * **Система → Пользователи** — создайте учётные записи;
   * **Система → Общие настройки / Ограничения / Безопасность** — при
     необходимости измените значения;
   * **Система → Фоновые задачи** — запустите очистку и проверку позже,
     когда появятся данные.

### 1.6. Состояние после установки

| Параметр | Значение по умолчанию |
|---|---|
| Модули `minecraft`, `cloud` | включены |
| Системные роли | `administrator` (20 прав), `user` (7 прав) |
| Квота Cloud по умолчанию | 50 ГБ |
| Квота Minecraft по умолчанию | 100 ГБ |
| Тома хранения | не зарегистрированы |
| Пользователи | только созданный администратор |
| Фоновые задачи | планировщик очереди, лимит `jobs.max_concurrent` |
