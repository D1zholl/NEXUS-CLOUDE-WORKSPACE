# Резервное копирование и восстановление

> Часть руководства администратора NEXUS WORKSPACE. Полный индекс — [ADMIN_GUIDE.md](../ADMIN_GUIDE.md).

## 10. Резервное копирование и восстановление

### 10.1. Что входит в резервную копию

| Данные | Обязательность | Комментарий |
|---|---|---|
| Дамп PostgreSQL | обязательно | пользователи, права, метаданные файлов, релизы, настройки, журнал |
| Каталоги хранения | обязательно | объекты `.nexus/objects`; пути — в `/system/storage`; копируются `backup-objects.ps1` |
| `.env`, `nexus.toml` | обязательно | секрет, БД, публичный URL, лимиты |
| Каталог `data` | если используется | скрипты копируют его автоматически |
| Логи | по желанию | для расследования инцидентов |
| `nexus.exe`, `frontend/dist` | не обязательно | восстанавливаются сборкой |

⚠ Дамп БД без объектов бесполезен: в нём есть ключи объектов, но нет
самих файлов. Объекты без БД также не видны приложению. Копируйте их
согласованно.

### 10.2. Windows

```powershell
# Полная копия (БД, data, конфигурация)
powershell -ExecutionPolicy Bypass -File deployment\backup.ps1 `
  -BackupDir D:\Backups -InstallDir C:\NexusWorkspace

# Только БД и конфигурация
powershell -ExecutionPolicy Bypass -File deployment\backup.ps1 `
  -BackupDir D:\Backups -SkipData
```

Скрипт создаёт каталог `<BackupDir>\<ГГГГММДД-ЧЧММСС>` с `database.dump`,
`data` (если не `-SkipData`), `.env`, `nexus.toml` и `manifest.json`.

⚠ Каталоги хранения вне `InstallDir\data` скрипт **не копирует**. Для них
используйте отдельный `backup-objects.ps1` (раздел 10.2.1).

### 10.2.1. Бинарные объекты (тома хранения)

`backup.ps1` сохраняет БД, `data` и конфигурацию, но не внешние тома. Объекты
`.nexus\objects`, `.nexus\staging` и `.nexus\quarantine` копирует отдельный
скрипт:

```powershell
# Все включённые тома из storage_volumes, incremental, хранить 7 наборов
powershell -ExecutionPolicy Bypass -File deployment\backup-objects.ps1 `
  -BackupDir D:\NexusObjectBackups -Retain 7 -Prune -Force

# Один том, полный набор
powershell -ExecutionPolicy Bypass -File deployment\backup-objects.ps1 `
  -BackupDir D:\NexusObjectBackups -VolumeRoot D:\NexusStorage -Mode Full
```

Результат — каталог `objects-<ГГГГММДД-ЧЧММСС>`:

```text
objects-20261120-135451/
  manifest.json          режим, согласованность, тома, SHA-256 каждого файла
  SHA256SUMS             контрольные суммы для переноса на другой носитель
  backup-result.json     итог запуска, сверка со storage_objects
  volumes/<id>/.nexus/objects|staging|quarantine/...
```

**Режимы.** `Full` копирует всё; `Incremental` (по умолчанию) добавляет только
файлы, у которых изменились размер или время изменения (объекты неизменяемы,
поэтому обычно это новые объекты). Раз в 7 дней автоматически создаётся новый
полный набор (`-FullEveryDays`, `0` отключает), поэтому цепочка не растёт
бесконечно. Для восстановления нужен полный набор и вся цепочка incremental
после него; `restore-objects.ps1` проверяет это по полю `base`.

**Согласованность и открытые файлы.** Windows не даёт скопировать файл,
открытый с несовместимым доступом. По умолчанию (`-Consistency Auto`) скрипт
снимает VSS-снимок тома (`Win32_ShadowCopy`, контекст `ClientAccessible`) и
копирует из него через временную символическую ссылку. Это требует прав
администратора и NTFS. Если VSS недоступен, скрипт останавливает службу
(`Pause`) на время копирования и запускает её в `finally`. Режим `Vss`
запрещает откат к остановке, `Pause` останавливает службу всегда, `Live`
копирует на живую с повторами `/R:3 /W:5` и **не гарантирует**
согласованность.

VSS-снимок crash-consistent: он фиксирует состояние файловой системы, но не
вызывает writer-ы приложений. Для объектов NEXUS этого достаточно (файл
появляется в `objects` только после полной записи), но дамп БД всё равно
снимайте отдельно и согласованно. Junction и симлинки не обходятся: Full
использует `robocopy /XJ`, Incremental — ручной обход с пропуском reparse
points, поэтому ссылка внутри тома не вытащит файлы за его пределы.

**Проверка.** Для каждого скопированного объекта скрипт считает SHA-256
потоково и сверяет размер/хэш с `storage_objects` (только `state='committed'`).
В манифест попадают `verified`, `missingOnDisk`, `hashMismatch`, `untracked`.
При расхождении запуск завершается успешно с предупреждением; для жёсткого
отказа используйте `-StrictDatabase`.

**Расписание.** Задача создаётся от `SYSTEM` с правами администратора:

```powershell
powershell -ExecutionPolicy Bypass -File deployment\backup-objects.ps1 `
  -BackupDir D:\NexusObjectBackups -RegisterTask -Schedule Daily -At 03:30 `
  -Mode Incremental -Retain 7

# Удалить задачу
... -UnregisterTask -TaskName NexusObjectsBackup
```

Задача запускает тот же скрипт с `-Prune -Force`; без `-Prune` старые наборы
не удаляются. **Удаление выполняется только по явному `-Prune`**; без `-Force`
скрипт спрашивает подтверждение, а в неинтерактивном режиме пропускает
удаление. Retention никогда не удаляет последний полный набор и наборы после
него: если цепочка длиннее `-Retain`, скрипт предупреждает и сохраняет базу
incremental.

**Восстановление.** Служба останавливается, наборы применяются от старых к
новым, затем проверяются SHA-256 и `storage_objects`, выдаются права и
служба запускается:

```powershell
# Полный набор
powershell -ExecutionPolicy Bypass -File deployment\restore-objects.ps1 `
  -BackupPath D:\NexusObjectBackups\objects-20261120-135451 -Force

# Цепочка full + incremental (или каталог со всеми наборами)
powershell -ExecutionPolicy Bypass -File deployment\restore-objects.ps1 `
  -BackupPath D:\NexusObjectBackups -Force
```

`-TargetRoot` восстанавливает единственный том в другой каталог (стенд,
проверка копии). Файлы, которых нет в наборе, restore **не удаляет**. Права
выдаются учётной записи службы (`StartName` из Win32_Service, иначе
`NT AUTHORITY\SYSTEM`) через `icacls /inheritance:e /grant:r ... /T`; отключить
можно `-SkipAcl`, задать другую учётную запись — `-AclAccount`.

После восстановления обязательно запустите «Проверить целостность» и
скачайте старый файл Cloud/релиз. Если объект был удалён из тома, до
восстановления скачивание вернёт `STORAGE_ERROR` — это ожидаемо.

### 10.3. Согласованность

Правильный порядок:

1. остановить службу (`Stop-Service NexusWorkspace`);
2. снять дамп БД;
3. скопировать каталоги хранения (`backup-objects.ps1` или VSS);
4. скопировать конфигурацию;
5. запустить службу.

Если остановка невозможна, используйте мгновенный снимок диска и БД:
копирование «на живую» может дать дамп, ссылающийся на ещё не
записанный объект. Скрипты этого не гарантируют.

### 10.4. Восстановление

**Windows:**

```powershell
powershell -ExecutionPolicy Bypass -File deployment\restore.ps1 `
  -BackupPath C:\NexusBackups\20261119-120000 `
  -InstallDir C:\NexusWorkspace
```

Скрипт останавливает службу, восстанавливает БД и `data`, копирует
конфигурацию, запускают `nexus check` и службу. Внешние каталоги хранения
восстанавливаются отдельно `restore-objects.ps1` (раздел 10.2.1) **до**
запуска службы: `restore.ps1` сам их не копирует.

Порядок ручного восстановления:

1. остановить службу;
2. восстановить БД (`psql ... -f database.sql`);
3. вернуть объекты в **те же пути**, что были зарегистрированы;
4. вернуть `.env`/`nexus.toml`;
5. выполнить `nexus check`;
6. запустить службу;
7. войти, открыть файл и запустить «Проверить целостность».

⚠ Путь тома после регистрации не редактируется. Если объекты восстановлены
в другой каталог, потребуется перерегистрация томов; без объектов удалить
регистрацию нельзя. Планируйте восстановление на исходные пути.

После восстановления проверьте:

* вход администратора и список пользователей;
* открытие старого файла Cloud и скачивание релиза;
* отсутствие `missing` после проверки целостности;
* журнал: нет ошибок `INTERNAL_ERROR`.

Храните копии вне сервера, ограничьте доступ (в `.env` лежит
`NEXUS_SECRET`) и регулярно проверяйте восстановление на тестовом стенде.
