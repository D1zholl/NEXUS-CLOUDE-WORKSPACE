# Пользователи, роли, права и квоты

> Часть руководства администратора NEXUS WORKSPACE. Полный индекс — [ADMIN_GUIDE.md](../ADMIN_GUIDE.md).

## 2. Пользователи, роли и права

### 2.1. Страница «Пользователи»

Открывается с правом `system.users.manage` (раздел **Система →
Пользователи**). Показывает имя, логин, роли, статус, последний вход,
занятое место, квоту и доступ к модулям. Поддерживает поиск по имени/логину
и фильтр `active` / `disabled`, по 25 записей на страницу.

Создание пользователя:

* логин — 3–32 символа, только латиница, цифры, `.`, `_`, `-`;
  после создания не меняется;
* отображаемое имя — 1–80 символов;
* пароль — 12–128 символов, буквы и цифры; проверяется сервером;
* статус — `Активен` или `Отключён`;
* роль по умолчанию — `user` (её можно снять или заменить);
* квота задаётся только при редактировании (раздел 3).

Редактирование позволяет изменить отображаемое имя, статус, роли,
персональную квоту и персональные исключения прав. Логин и пароль здесь не
меняются.

Действия в строке пользователя:

| Действие | Что делает | Ограничения |
|---|---|---|
| Сбросить пароль | задаёт новый пароль и **отзывает все сессии** пользователя | недоступно для собственной учётной записи |
| Снять блокировку | сбрасывает `failed_login_attempts` и `locked_until` | не очищает in-memory лимитер IP+логин |
| Отозвать сессии | завершает все активные сессии | доступно всегда |
| Удалить | удаляет учётную запись | нельзя удалить себя и последнего активного суперадминистратора |

Отключение пользователя (`disabled`) немедленно запрещает вход, но не
завершает уже открытые сессии. Чтобы выгнать его из системы, нажмите
«Отозвать сессии». Собственную учётную запись отключить нельзя — сервер
вернёт ошибку валидации.

Блокировка входа работает на двух уровнях:

* **5 неудачных попыток за 15 минут** на пару IP+логин → ответ
  `RATE_LIMITED` на 15 минут (в памяти процесса);
* **10 неудачных попыток** по аккаунту → `ACCOUNT_LOCKED` на 15 минут
  (`locked_until` в БД).

Кнопка «Снять блокировку» снимает только блокировку в БД. Лимитер в памяти
сбрасывается перезапуском службы или ожиданием 15 минут. Неудачные попытки
пишутся в журнал (`auth.login.failed`) с причиной.

⚠ Не отключайте и не удаляйте последнего администратора: сервер это
запрещает, но восстановление доступа потребует CLI `create-admin`.

### 2.2. Роли

Страница **Система → Роли и права** показывает карточки ролей: название,
ключ, описание, количество пользователей и прав. Системные роли
(`administrator`, `user`) нельзя изменить или удалить; они помечены бейджем
«системная».

Создание роли:

* ключ — 3–48 символов, латиница в нижнем регистре, цифры, `.`, `_`, `-`;
  после создания не меняется;
* название — до 80 символов, описание — до 400;
* права выбираются галочками по модулям.

Удалить роль, назначенную хотя бы одному пользователю, нельзя
(`ROLE_IN_USE`). Сначала снимите её у пользователей.

### 2.3. Модель прав

Права вычисляются на сервере при каждом запросе:

1. суперадминистратор получает все 20 прав и обходит проверки;
2. права ролей объединяются;
3. персональное «Разрешить» добавляет право;
4. персональное «Запретить» **всегда побеждает** роль и «Разрешить».

Изменения прав применяются со следующего запроса пользователя. Открытая
вкладка хранит прежний список прав до перезагрузки страницы или повторного
входа, поэтому после изменения попросите пользователя обновить страницу.

Каталог прав (20):

| Модуль | Право | Назначение |
|---|---|---|
| Minecraft | `minecraft.view` | просмотр сборок |
| Minecraft | `minecraft.build.create` | создание сборок |
| Minecraft | `minecraft.build.edit` | редактирование сборок |
| Minecraft | `minecraft.build.publish` | публикация релизов |
| Minecraft | `minecraft.build.delete` | удаление сборок |
| Minecraft | `minecraft.artifacts.upload` | загрузка файлов сборок |
| Launcher | `launcher.manage` | управление токенами лаунчера |
| Cloud | `cloud.view` | доступ к облачному хранилищу |
| Cloud | `cloud.file.upload` | загрузка файлов |
| Cloud | `cloud.file.download` | скачивание файлов |
| Cloud | `cloud.file.delete` | удаление файлов |
| Cloud | `cloud.file.share` | общий доступ к файлам |
| Cloud | `cloud.folder.create` | создание папок |
| Cloud | `cloud.storage.manage` | зарезервировано; текущие маршруты требуют `system.storage.manage` |
| Система | `system.view` | просмотр состояния, журнала, задач |
| Система | `system.users.manage` | пользователи и роли |
| Система | `system.storage.manage` | диски и тома |
| Система | `system.settings.manage` | системные настройки |
| Система | `system.monitoring.view` | данные мониторинга |
| Система | `system.jobs.manage` | запуск, пауза, продолжение и отмена задач |

Встроенная роль `user` содержит 7 прав: `minecraft.view`, `cloud.view`,
`cloud.file.upload`, `cloud.file.download`, `cloud.file.delete`,
`cloud.file.share`, `cloud.folder.create`.

Практические правила:

* не выдавайте `system.settings.manage` и `system.users.manage` без
  необходимости;
* для сопровождения достаточно `system.view` + `system.monitoring.view` +
  `system.jobs.manage`;
* `cloud.storage.manage` в интерфейсе не используется — управление томами
  идёт через `system.storage.manage`;
* проверяйте итог с точки зрения пользователя: «Профиль» показывает его
  роли, число прав и режим доступа.

## 3. Квоты

### 3.1. Как считается квота

Квота — логический лимит, а не резервирование места на диске. Эффективная
квота:

1. персональное значение `users.quota_bytes`, если оно задано;
2. иначе значение по умолчанию из `quota_defaults` для области (`cloud` или
   `minecraft`).

⚠ Использованное место (`storage_usage.used_bytes`) **общее** для Cloud и
Minecraft: занятый объём учитывается суммарно. Область влияет только на
значение по умолчанию. Если задать пользователю персональную квоту, она
применяется к обеим областям.

Квота проверяется сервером при создании новой загрузки с учётом замены
файла: при перезаписи учитывается разница `новый размер − старый размер`.
Удаление файлов освобождает место. При превышении возвращается
`413 QUOTA_EXCEEDED` с деталями `limitBytes`, `usedBytes`,
`requestedBytes`, `scope`.

### 3.2. Управление

**Система → Пользователи → Редактировать → Квота хранения, ГБ.**

* пустое поле — использовать значение по умолчанию;
* число — персональная квота в гигабайтах (целое, больше нуля);
* квота действует на Cloud и Minecraft одновременно.

Значения по умолчанию после миграции `0008_quotas.sql`:

| Область | Значение |
|---|---|
| Cloud | 50 ГБ (53 687 091 200 байт) |
| Minecraft | 100 ГБ (107 374 182 400 байт) |

### 3.3. Изменение значений по умолчанию

Ключи `limits.quota_cloud_gb` и `limits.quota_minecraft_gb` на странице
**Ограничения** сразу обновляют `quota_defaults` (ГБ переводятся в байты)
и инвалидируют кэш настроек. Перезапуск не нужен. При необходимости те же
значения можно изменить напрямую в таблице:

```sql
-- Пример: Cloud 200 ГБ, Minecraft 300 ГБ
update quota_defaults set bytes = 214748364800, updated_at = now()
where scope = 'cloud';
update quota_defaults set bytes = 322122547200, updated_at = now()
where scope = 'minecraft';
```

Перезапуск не нужен: значение читается при каждой проверке. Персональные
квоты пользователей имеют приоритет и не меняются.

Рекомендации:

* держите запас 10–15% на staging, журналы и временные объекты;
* квота не спасает от переполнения диска — контролируйте свободное место
  (раздел 4);
* перед массовым изменением квот предупредите пользователей: превышение
  проявится при следующей загрузке.
