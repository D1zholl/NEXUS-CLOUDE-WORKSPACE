# Обновление, типовые ошибки и регламент

> Часть руководства администратора NEXUS WORKSPACE. Полный индекс — [ADMIN_GUIDE.md](../ADMIN_GUIDE.md).

## 11. Обновление

### 11.1. Штатный порядок

**Windows** (от администратора):

```powershell
powershell -ExecutionPolicy Bypass -File deployment\update-windows.ps1
```

Скрипт:

1. делает резервную копию (`backup.ps1` / дамп + `data`);
2. собирает backend и frontend;
3. останавливает службу;
4. сохраняет предыдущий бинарник (`nexus.previous.exe`) и заменяет файлы;
5. применяет миграции и выполняет `check`;
6. при ошибке миграции возвращает предыдущий бинарник и запускает службу;
7. запускает службу и печатает статус.

⚠ Скрипт не копирует внешние каталоги хранения. Перед обновлением сделайте
их отдельную копию.

⚠ Откат автоматически возвращает только **бинарник**. Миграции БД
forward-only и не откатываются. Если новая версия изменила схему и работу
нужно отменить, восстанавливайте БД из копии, снятой перед обновлением.

### 11.2. Ручное обновление

1. Снимите резервную копию (раздел 10).
2. Остановите службу.
3. Замените `nexus`/`nexus.exe` и содержимое `frontend`.
4. Выполните `nexus migrate`.
5. Выполните `nexus check`.
6. Запустите службу.
7. Проверьте вход, файлы, релизы и журнал.

Держите предыдущий бинарник до подтверждения работоспособности. Не
запускайте две копии NEXUS на одном порту или против одной БД.

### 11.3. Проверка после обновления

* `nexus --version` и версия в «Состоянии системы» совпадают;
* `nexus check` — код 0;
* служба `Running`/`active`;
* вход и выход работают, CSRF не отвергает запросы;
* загрузка и скачивание файла;
* список сборок и публикация тестового релиза (если модуль включён);
* «Проверить целостность» — без новых `missing`;
* в логах нет повторяющихся `ERROR`.

## 12. Типовые ошибки

| Симптом / код | Причина | Действие |
|---|---|---|
| На входе «В системе ещё нет пользователей» | таблица `users` пуста | `nexus create-admin --username admin` |
| `INVALID_CREDENTIALS` | неверный логин/пароль | проверьте раскладку и регистр; сбросьте пароль |
| `ACCOUNT_LOCKED` | 10 неудач, блокировка 15 минут | подождите или «Снять блокировку» |
| `RATE_LIMITED` | 5 неудач за 15 минут по IP+логину | подождите 15 минут; при необходимости перезапустите службу |
| `ACCOUNT_DISABLED` | статус `disabled` | включите пользователя |
| `SESSION_EXPIRED` | истёк TTL или сессия отозвана | войдите снова |
| `CSRF_INVALID` | сменился `NEXUS_SECRET` или страница устарела | обновите страницу; задайте постоянный секрет |
| `403 MODULE_DISABLED` | модуль отключён | включите в «Состоянии системы» |
| `404` на `/api/v1/launcher` | модуль `minecraft` отключён | это ожидаемое поведение; включите модуль |
| `NO_VOLUME_AVAILABLE` | нет подходящего тома | добавьте/включите/проверьте том, освободите место |
| `VOLUME_UNAVAILABLE` | том offline/error или выключен | проверьте путь и права, нажмите «Проверить» |
| `INSUFFICIENT_SPACE` | свободно меньше резерва или размера файла | освободите место или уменьшите резерв |
| `VOLUME_NOT_EMPTY` | в томе есть объекты | удалите данные через приложение, затем регистрацию |
| `VOLUME_EXISTS` / пересечение путей | каталог уже зарегистрирован | выберите другой каталог |
| `QUOTA_EXCEEDED` | превышена квота пользователя | увеличьте персональную квоту или `limits.quota_*_gb` |
| `FILE_TOO_LARGE` | файл больше `limits.max_upload_mb` | увеличьте лимит или разбейте файл |
| `CHUNK_TOO_LARGE` | чанк больше `limits.chunk_max_mb` | увеличьте лимит в настройках; клиент получит новый `chunkMaxBytes` из `/cloud/config` |
| `UPLOAD_NOT_ACTIVE` / `UPLOAD_INCOMPLETE` | сессия истекла или не все чанки получены | начните загрузку заново |
| `UPLOAD_OFFSET_MISMATCH` | клиент и сервер разошлись по смещению | повторите с серверного `Upload-Offset` |
| `UPLOAD_DATA_MISSING` | потерян staging-файл | начните загрузку заново |
| 502/504 от прокси | служба не запущена или порт не совпадает | проверьте службу, `NEXUS_PORT`, `proxy_pass` |
| `check`: «NEXUS_SECRET оставлен значением по умолчанию» | секрет не заменён | задайте 32+ случайных символа |
| `check`: «каталог статики не найден» | не собран frontend | `npm run build`, проверьте `NEXUS_STATIC_DIR` |
| `check`: «администратор не создан» | нет суперадминистратора | `nexus create-admin` |
| `check`: «тома хранения не зарегистрированы» | предупреждение | добавьте каталог в «Хранилищах» |
| Задача `failed` | ошибка ФС/БД/пути | откройте ошибку в «Фоновых задачах», проверьте лог |
| История мониторинга пуста | первый запуск или очистка метрик | подождите 10 секунд |
| Том offline после перезагрузки | диск/путь не смонтированы | смонтируйте, проверьте права, «Проверить» |

Если ошибка не описана:

1. запишите время, пользователя, действие и `request_id` из ответа;
2. найдите событие в журнале действий;
3. найдите `request_id`/ошибку в логе приложения;
4. проверьте `nexus check` и свободное место;
5. не удаляйте объекты и не пересоздавайте БД до снятия копии.

## 13. Регламент администратора

| Периодичность | Проверки |
|---|---|
| Ежедневно | служба работает; `/api/v1/health` = `ok`; ошибки в «Фоновых задачах»; свободное место > 15% |
| Еженедельно | журнал входов и опасных операций; временные загрузки и ссылки; резервная копия создана |
| Ежемесячно | проверка целостности; пересмотр ролей и квот; тест восстановления; обновление |
| При инциденте | сохранить копию; зафиксировать `request_id`; не удалять улики; при компрометации сменить `NEXUS_SECRET`, пароли и токены |

Минимальный production-чек-лист:

* HTTPS и `NEXUS_COOKIE_SECURE=true`;
* постоянный `NEXUS_SECRET` (32+ символа), `.env` недоступен пользователям;
* PostgreSQL слушает только localhost/внутреннюю сеть;
* отдельные учётные записи, минимум администраторов;
* резервные копии БД и каталогов хранения проверены восстановлением;
* журналы и место на дисках контролируются;
* обновление проходит через резервную копию и `nexus check`.
