# J4: приёмка после перезагрузки Windows

Дата: 20.11.2026. Стенд: Windows 11 Pro 10.0.26300, PostgreSQL 17.12,
служба `NexusJ4` (LocalSystem, `Automatic`, зависимость
`postgresql-x64-17`), установка `C:\ProgramData\NexusJ4`.

## Как выполнялось

```powershell
# До перезагрузки: служба, файл 2 МиБ, публичная ссылка,
# незавершённая загрузка 512 КиБ из 1 МиБ, running-задача.
powershell -File tests\reboot-acceptance.ps1

# После старта Windows автоматически:
#   NexusJ4RebootVerify (SYSTEM, At startup)
#   powershell -File tests\reboot-acceptance.ps1 -Phase Verify
```

## Наблюдение: прогрев PostgreSQL

Сразу после boot `health` был `ok`, но через ~1,5 минуты на короткое время
показал `database: down`; в журнале в это время были медленные запросы
(`system_settings`, `system_metrics`) с задержкой 4–9 с. Через ~15 с
`health` снова стал `ok` **без ручного вмешательства** — это холодный старт
PostgreSQL/кэша и фоновая очередь обслуживания, а не отказ службы. Если такое
повторится после Windows Update, смотреть журнал PostgreSQL и
`system.jobs`; для production можно увеличить `shared_buffers`/прогрев.

## Очистка

После снятия отчёта служба `NexusJ4`, временный каталог
`C:\ProgramData\NexusJ4` и задача `NexusJ4RebootVerify` удалены; временный
администратор `j4reboot` удалён вместе с тестовыми объектами (каскад FK).
