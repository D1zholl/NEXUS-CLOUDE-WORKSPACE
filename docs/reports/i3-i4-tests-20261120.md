# I3/I4 — добор тестов (20.11.2026)

Сессия I3/I4 закрывала **непокрытые области**, а не общий счётчик: цели
(≥30 frontend, ≥180 backend) были превышены ещё до сессии. Поэтому ниже
зафиксировано, что именно отсутствовало, что добавлено и какой получен

## 3. Что считалось недостающим

Проверка фактических имён тестов показала: в B–H уже были HTML/JS-preview,
подделка `Content-Type`, лимиты 2000 файлов/100 уровней, auth-only ссылки на
backend, пауза/возобновление задач на backend. Эти сценарии **не дублировались**.

| Область | Чего не было |
|---|---|
| Frontend settings | компонентных тестов `SettingsGroupPage`: фильтр группы, сохранение int, read-only `network.*` |
| Frontend shares | UI auth-only ссылки и пароля на `PublicSharePage` |
| Frontend preview | точных границ лимитов, dotfiles/составных расширений, текста > 512 КБ по `Content-Length` |
| Frontend jobs | паузы/возобновления через строку `JobsPage` |
| Frontend uploadQueue | полного вложенного пути в `ensureFolder` и независимости групп папок |
| Backend settings | HTTP-коды/права, пользовательский фон, приоритет `quality`, actor/updated_at, upsert, независимость кеша |
| Backend jobs | фильтров списка, деталей/404, конфликтов pause/resume/cancel, валидации maintenance, прав и аудита |
| Backend realtime | отказа до Upgrade без/с неверной сессией, ping/pong, независимости вкладок |
| Backend cloud | деталей/breadcrumb, update/rename/star/move, поиска/сортировки/пагинации, статуса и abort загрузки, списка/отзыва ссылок, пароля/лимита скачиваний, HTTP-экспорта, purge/пустой корзины, чужих `parentId` |
| Backend launcher | истёкшего токена, отсутствующего/неверного токена и `X-Launcher-Token`, прав admin-маршрутов, отказа 401/403 до расхода квоты, HTTP-изоляции двух токенов |
| Backend manifest | пустого релиза, отключённого файла, category/side/required, относительных уникальных `download_url` |
| Backend security content | SVG, XHTML/XML, Range-обход attachment, инъекция в `Content-Disposition`, JSON с `<script>` |

## 6. Надёжность на Windows

* **Без sleep-ожиданий.** Новые тесты ждут состояние через `waitFor` /
  `vi.waitFor` / цикл с дедлайном; фиксированных пауз «подождать N секунд» нет.
* **Без абсолютных путей.** Все фикстуры строятся от `tempfile`/`TestEnv`;
  пути томов и файлов вычисляются от временного корня.
* **Удаление temp с retry.** `tests/common/mod.rs` использует `RetryTempDir`:
  `remove_dir_all` повторяется до 20 раз по 25 мс, потому что на Windows файл
  может быть кратковременно залочен антивирусом/индексатором.
* Прогон выполнялся на Windows 11/NTFS.
